The FX special effects image operator applies mathematical expressions to each pixel channel of an image. The FX expression language provides a flexible mechanism for fine-grained pixel-level transformations, analysis, and procedural generation.

Procedural Generation

Create procedural canvases, gradients, and mathematical colormaps from equations.

Geometric Distortion

Translate, flip, mirror, rotate, scale, shear, and warp images using custom coordinate functions.

Compositing & Routing

Move color values between images and channels, convolve neighboring pixels, and merge multiple inputs.

Image Metrics

Compute statistical metrics, evaluate properties, and generate custom image "fingerprints."

Sequence Processing (-fx vs. +fx): The operator loops through all pixels and active channels, replacing the entire image sequence with a modified clone of the first image (u). Other images in the sequence serve only as reference data unless +fx is used to apply the expression to every image in the sequence individually.
Threading & Execution: FX expressions are compiled in a single thread, then executed across multiple threads in parallel unless the expression calls debug(), which forces single-threaded execution for clean console output.

3. Variable Assignments & Radial Gradients

Variable assignments (Xi, Yj) reduce expression complexity and enable multi-step calculations such as constructing a radial gradient:

$ magick -size 70x70 canvas: \
  -fx "Xi=i-w/2; Yj=j-h/2; 1.2*(0.5-hypot(Xi,Yj)/70.0)+0.5" \

Inject Box-Muller Gaussian random noise scaled per color channel:

$ magick photo.jpg -fx 'iso=32; rone=rand(); rtwo=rand(); \
  myn=sqrt(-2*ln(rone))*cos(2*Pi*rtwo); myntwo=sqrt(-2*ln(rtwo))* \

Use an iterative for() loop to render a Julia set fractal and map escape iterations through a color lookup table (-clut):

$ magick -size 400x400 xc:gray -fx " \
  Xi=2.4*i/w-1.2; \
  Yj=2.4*j/h-1.2; \
  for (pixel=0.0, (hypot(Xi,Yj) < 2.0) && (pixel < 1.0), \
    delta=Xi^2-Yj^2; \
    Yj=2.0*Xi*Yj+0.2; \
    Xi=delta+0.4; \
    pixel+=0.00390625 \
  ); \
  pixel == 1.0 ? 0.0 : pixel" \
  \( -size 1x1 xc:white xc:red xc:orange xc:yellow xc:green1 xc:cyan xc:blue \

Operator Precedence (Highest to Lowest)
  • 1. Exponentiation: ^
  • 2. Unary & Multiplicative: unary -, *, /, %
  • 3. Additive & Bitwise Shift: +, -, <<, >>
  • 4. Relational & Equality: <, <=, >, >=, ==, !=
  • 5. Compound Assignment & Inc/Dec: +=, -=, *=, /=, %=, <<=, >>=, &=, |=, ++, --
  • 6. Bitwise & Logical: &, |, &&, ||, ~ (logical NOT)
  • 7. Ternary Conditional: ?:
  • 8. Statement Assignment & Separator: =, ;
Operator Semantics & Boolean Rules
Equality & Relational (==, !=, <, <=, >, >=)
Returns 1.0 when true and 0.0 when false. == and != compare values within Epsilon (1e-12).
Logical Connectives (&&, ||, ~)
x && y returns 1.0 if x > 0 and y > 0; x || y returns 1.0 if either > 0; ~x (logical NOT) returns 1.0 if not x > 0. Bitwise AND/OR use & and |.
Ternary (cond ? true-stmts : false-stmts)
Evaluates true-stmts if cond != 0, otherwise false-stmts. Only one ternary conditional is allowed per statement.
Loops & Branches (if, for, while, do)
if(cond, nonzero, zero), for(init, cond, stmts), while(cond, stmts), and do(cond, stmts) iterate while cond != 0.
Syntax & Semantics Rules
  • Case Insensitivity: Symbols and built-in identifiers are case insensitive.
  • Statements & Assignments: Statements are separated by ; and consist of variable assignments or the final return expression. Assignment starts a statement—it is not an operator—and at most one ternary conditional (x ? y : z) is permitted per statement.
  • Variable Naming: Single-character names are reserved for built-ins; assigning to one throws an exception (e.g., r=3.0; r raises Attempted assignment to non-UserSymbol 'r'). Custom variables must use two or more letters only (e.g., Xi, not X1).
  • Unary vs. Binary Precedence: Unary operators have lower precedence than exponentiation: -3^2 evaluates as -(3^2) = -9. Use parentheses ((-3)^2 = 9) to override.
  • Division & Implicit Multiplication: 1/2x is parsed as (1/2)x; write 1/(2*x) explicitly when dividing by a product.
  • Subtracting Negative Numbers: Because -- is the decrement operator, wrap negative right-hand operands in parentheses: -4-(-5).

Source Images, Pixel Addressing & Channels

Image Sequence Indexes

u and v reference the first and second images in the sequence. Index any image reference with brackets (0-based; negative indexes count from the end; out-of-range indexes wrap around, so in a 3-image list u[-1], u[2], and u[5] all select the third image):

  • u[0] First image
  • u[2] Third image
  • u[-1] Last image in list
  • u[t] Current image (s)

Average the first and third images (the second image at index 1 is ignored and discarded):

$ magick image1.jpg image2.jpg image3.jpg -fx "(u+u[2])/2" image.jpg
Pixel & Neighborhood Access

All color values are normalized to 0.0–1.0 (alpha ranges from 0.0 transparent to 1.0 opaque). By default, p, r, g, b, and a read from s (equivalent to u except inside %[fx:...]).

Relative Indexing (Brackets):
p[-1].g
Green value of pixel immediately left of current pixel
p[-1,-1].r
Red value of pixel diagonally up and left
Absolute Coordinates (Braces):
p{0,0}.r
Red value of upper-left corner pixel
p{12,34}.b
Blue value at column 12, row 34

Fractional coordinates return blended colors according to -interpolate, and out-of-bounds coordinates follow -virtual-pixel.

Channel Selection & Output Channels

Use -channel to choose which output channels -fx updates (by default, all channels except opacity are updated). Appending a channel qualifier such as u.r reads a specific input channel; omitting it reads the active channel. Use mean.this for the current channel's mean or mean.all for the overall mean across channels.

Replace the red channel of alpha.png with the average of the green channels from alpha.png and beta.png:

$ magick alpha.png beta.png -channel red -fx "(u.g+v.g)/2" gamma.png

Because only the first image (u) is cloned and modified on the selected -channel green, blending a flopped logo with an unflopped logo produces an asymmetric result:

$ magick logo: -flop logo: -resize "20%" -channel green -fx "(u+v)/2" image.jpg

Results & Format Escapes

When -fx runs, computed channel values are written into a clone of u (s = u, t = 0), which then replaces the entire input image list. Instead of modifying image pixels, FX expressions can also be evaluated inside -format and -set string escapes:

%[fx:...] Value Escape

Evaluated once per image in the sequence (s and t step through each image, i = j = 0, channel defaults to red, and -channel is ignored).

$ magick canvas:'rgb(25%,50%,75%)' rose: -colorspace gray \
  -format 'Red channel of NW corner of image #%[fx:t] is %[fx:s] ' info:
Red channel of NW corner of image #0 is 0.464883
Red channel of NW corner of image #1 is 0.184582
%[pixel:...] & %[hex:...] Color Escapes

Evaluated once per image and per color channel (-channel ignored, i = j = 0), converting the resulting channel values into a named or hexadecimal color string.

$ magick rose: -format '%[pixel:p{0,0}]' info:
Practical Escape Examples

Rotate each duplicated frame proportionally and set a longer animation pause on the first frame (t == 0):

$ magick rose: -duplicate 29 -virtual-pixel Gray -distort SRT '%[fx:360.0*t/n]' \
  -set delay '%[fx:t == 0 ? 240 : 10]' -loop 0 rose.gif

Compare two images with RMSE and return 1 if the distortion exceeds 0.1 (otherwise 0):

$ magick water.png reference.png -metric RMSE -compare -format "%[fx:%[distortion]>0.1]" info:

Convert an image modification date-time property into Unix epoch seconds using epoch():

$ magick rose.png -precision 16 -format '%[fx:epoch(%%[date:modify])]' info:
