Establish a Local Security Policy

ImageMagick’s security model is “everything allowed unless denied,” and the last matching policy wins. Place broad deny rules first, followed by specific exceptions, to avoid accidental authorization[cite: 8].

ImageMagick is intentionally open by default to support controlled environments like Docker containers or sandboxed pipelines.

Security balances protection against vulnerabilities with operational convenience. The policy acts as your control point between strict lockdown and developer flexibility[cite: 8].

Limit High-Risk Coders Disable unsafe vector and network modules.
Constrain Resources Prevent denial-of-service via massive images.

Selecting the Right Security Policy

Choose from four predefined baseline security policies provided as of version 7.1.1-16:

open
Default

Designed for secure settings like firewalls or Docker containers. Offers broad resource access and flexibility, but presents vulnerabilities in less regulated conditions[cite: 8].

limited
Balanced

Finds a middle ground by deactivating hazardous coders (like SVG or HTTP) and setting adjustable constraints on memory, storage, and duration.

secure
Strict

Prioritizes rigorous controls, restrictive limits, and explicit path approvals for reading/writing, sequence lengths, and remote connection passphrases.

websafe
Public Web

Restricts reading/writing strictly to web-safe formats (GIF, JPEG, PNG) and disables image filters and indirect reads for public contexts.

Example Hardened Security Policy

A production-ready hardened configuration for untrusted web environments:

<?xml version="1.0" encoding="UTF-8"?>
<policymap>
  <policy domain="resource" name="thread" value="4"/>
  <policy domain="resource" name="time" value="60"/>
  <policy domain="resource" name="file" value="768"/>
  <policy domain="resource" name="memory" value="256MiB"/>
  <policy domain="resource" name="map" value="512MiB"/>
  <policy domain="resource" name="area" value="32MP"/>
  <policy domain="resource" name="disk" value="1GiB"/>
  <policy domain="resource" name="list-length" value="16"/>
  <policy domain="resource" name="width" value="4KP"/>
  <policy domain="resource" name="height" value="4KP"/>
  <policy domain="cache" name="memory-map" value="anonymous"/>
  <policy domain="cache" name="synchronize" value="true"/>
  <policy domain="delegate" rights="none" pattern="*"/>
  <policy domain="filter" rights="none" pattern="*"/>
  <policy domain="path" rights="none" pattern="-"/>
  <policy domain="module" rights="none" pattern="*"/>
  <policy domain="module" rights="read | write" pattern="{GIF,JPEG,PNG,WEBP}"/>
</policymap>

Pixel Cache Synchronize Policy

Memory-mapping disk caches increases performance by up to 5x, but can trigger OS SIGBUS signals if disk space exhausts. Enforce synchronization to guarantee safety:

<policy domain="cache" name="synchronize" value="True"/>

Other Security Best Practices

Follow these recommended guidelines to maintain a secure deployment:

1. Use Web-Safe Formats

Limit processing to GIF, JPEG, and PNG where possible.

2. Enable Sandboxing

Run ImageMagick within restricted environments to protect host systems.

3. Absolute Delegate Paths

Configure delegates with absolute paths (e.g., /usr/bin/gs) using --with-frozenpaths=yes.

4. Guard External Pipes

Deny pipe inputs with path policies if command execution is not required.
